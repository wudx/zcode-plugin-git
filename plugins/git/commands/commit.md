---
description: 分析变更并生成提交信息，确认后提交
---

用 AI 生成提交信息并提交当前仓库的变更。严格按以下步骤执行：

1. 调用 `git_status` 工具查看当前仓库状态。
2. 如果暂存区为空：
   - 若工作区也没有任何修改，告知用户没有可提交的变更，结束。
   - 否则询问用户是否把全部修改加入暂存区（列出文件），用户确认后再调用 `git_stage`；用户拒绝则结束。
3. 对暂存区的每个文件调用 `git_diff`（`staged: true`）获取暂存 diff。如果 diff 总量过大，优先看文件名与状态，取前若干个文件的 diff。
4. 基于暂存内容生成提交信息：
   - 符合 Conventional Commits 风格：`type(scope): 摘要`，摘要不超过 72 字符。
   - 常用 type：feat / fix / docs / style / refactor / perf / test / chore。
   - 摘要使用仓库最近提交的主要语言（可先用 `git_log` 参考）。
   - 改动较多时，空一行后用 `-` 列出要点。
5. 向用户展示生成的提交信息，并询问确认（或让用户给出修改意见）。用户确认前不要提交。
6. 用户确认后调用 `git_commit` 提交，报告提交结果（commit hash）。

安全约束：
- 绝不执行 discard / restore / checkout 等会丢失修改的操作，除非用户明确要求。
- 不使用 --amend、--no-verify 或强制参数。
- 提交信息只来自第 4 步生成并经用户确认的内容。
